## 1. 项目概述 ✅ 已实现

### 1.1 核心理念

**LLM 做高层决策，规则做底层执行。**

- **规则引擎负责确定性决策**：攻击可见特感、救助被控队友、Tank 集火等 — 零延迟、零 API 开销
- **LLM 负责复杂场景决策**：需要战术判断的场景 — 有延迟但更智能
- **SourcePawn 规则负责"怎么做"**：执行具体操作（瞄准、移动、射击、拾取等）

### 1.2 为什么不用 LLM 做所有决策

| 问题 | 说明 | 实际数据 |
| :--- | :--- | :--- |
| 延迟 | LLM API 延迟 0.3–2s，但战斗决策需要 10ms 级响应 | 规则引擎 ~0ms, LLM 平均 800ms |
| 成本 | 每秒 1 次调用，每天约 8.6 万次 | STATE 变化检测跳过 68.5% 请求 |
| 可靠性 | API 可能超时/失败，必须有规则引擎兜底 | 规则引擎覆盖 13.4% 决策，无需 API |
| 精度 | LLM 无法精确控制瞄准角度、移动速度等连续量 | LLM_ClearMoveOverride + SetMoveToPosition |

### 1.3 与现有插件的关系

本系统**集成在 IB (L4D2-Survivor-Bot-AI-Improver) 插件内部**，而非独立插件：

```
LLM 决策层 (Python 服务 + 规则引擎)
    ↓ TCP 决策指令
IB 集成层 (l4d2_sb_ai_improver.sp 内 LLM 模块)
    ↓ LLM_ApplyStrategy() 直接修改 IB 内部变量
IB 执行层:
  - ib_gren, ib_evade_*, ib_defib_revive (原有功能)
  - SetMoveToPosition, L4D2_CommandABot (LLM 控制)
  - 底层 AI 行为 (射击、移动、拾取)
```

**关键设计决策**：LLM 模块直接集成在 IB 插件源码中，而非独立插件。优势：
1. 直接访问 IB 内部变量（g_iBot_MovePos_Priority 等），无需跨插件通信
2. 可直接调用 IB 的 SetMoveToPosition、CommandABot 等内部函数
3. 避免 SourcePawn 跨插件调用的性能开销和兼容性问题

## 4. LLM 交互设计 ✅ 已实现

### 4.1 实际 System Prompt

```
你是 L4D2 生还者 bot 的高层决策大脑。

简单威胁（可见特感、Tank、愤怒 Witch）已由规则引擎处理，你只处理需要战术判断的复杂场景。

决策原则:
1. 救被控/倒地队友最高优先级（除非有 Tank 逼近且你是唯一输出）
2. 血量低于 30 时优先自保/治疗
3. Witch 未惊扰时保持距离，不要主动攻击
4. 窄道中优先使用近战和手雷
5. 有土制炸弹/胆汁罐时，遇到尸潮应投掷
6. Tank 战优先集火，闪避石头
7. 终局救援时优先上载具

绝对禁止:
- 永远不要在有可见威胁时选择 follow_team
- 不要对愤怒 Witch 选择保持距离（必须攻击或已交战）
- 不要在队友被控时选择 follow_team
- 不要在自身倒地时选择 use_defib（无法对自己使用）

数据权威层级: 威胁 > 队友状态 > 事件

回复格式 (严格遵守):
{"action":"行动名","target":"目标名","reason":"简短理由"}
```

### 4.2 用户 Prompt 模板

```
当前游戏状态:
{state_json}

上一决策: {last_action} ({last_action_time_ago}秒前)

可选行动:
1. help_teammate - 救被控/倒地队友 (target=队友名)
2. heal_teammate - 给队友治疗物品
3. attack_si - 攻击特感 (target=类型名)
4. attack_tank / attack_witch
5. throw_grenade - 扔手雷 (target=grenade_type)
6. evade_threat - 闪避威胁 (target=threat_type)
7. pick_up_item / give_item
8. follow_team / hold_position / use_defib

回复格式 (严格遵守):
{"action":"行动名","target":"目标名","reason":"简短理由"}
```

### 5.3 核心模块

- **L4D2_CommandABot**：用于 evade_threat 等需要立即响应的行动
- **g_fLLM_ActionExpire**：决策 5 秒过期，超时自动回退 follow_team
- **next_interval**：Python 返回间隔建议，SourceMod 动态调整 ib_llm_interval ConVar

### 6.2 决策流程

```
STATE 到达 → 变化检测 → 规则引擎 → ModelRouter(LLM) → 后处理校验 → 返回决策
              ↓ skip      ↓ 命中      ↓ +PlayerScorer   ↓ validate    ↓ record
           复用上次    直接返回    评分建议注入      against_state   MapExperience
           决策       (13.4%)    +地图经验注入      覆盖误判         (SQLite)
           (68.5%
            被跳过)

ROUND_OUTCOME 到达 → MapExperience.record_round_outcome → SQLite pending → 实际结果
```

## 8. 规则引擎 ✅ 已实现（新增）

### 8.1 设计思路

规则引擎在 LLM 调用前执行确定性决策，覆盖不需要战术判断的明显场景：
- 零延迟（~0ms vs LLM 平均 800ms）
- 零 API 开销
- 结果可预测、可调试

### 8.2 已实现规则

| 规则 | 条件 | 决策 | 优先级 |
| :--- | :--- | :--- | :--- |
| Rule 0 | 自身倒地 | `hold_position` | 最高（自保优先） |
| Rule 1 | 可见 Tank (非 ghost) | `attack_tank` | 高 |
| Rule 2 | 可见非 ghost 特感 | `attack_si` (优先级: charger/smoker > hunter > jockey > boomer/spitter) | 高 |
| Rule 3 | 愤怒 Witch | `attack_witch` | 高 |
| Rule 4 | 队友被控 (pinned) | `help_teammate` (critical) | 最高 |
| Rule 5 | 队友倒地 (incap) | `help_teammate` (high) | 高 |
| Rule 6 | B&W 队友 + 有治疗物品 | `heal_teammate` | 中 |

### 8.3 特感攻击优先级

```python
SI_PRIORITY = {
    "charger": 1, "smoker": 2,  # 正在控制队友 → 最高优先
    "hunter": 3,                  # 即将造成伤害
    "jockey": 4,                  # 较慢威胁
    "boomer": 5, "spitter": 6,   # 间接威胁
}
```

## 9. 决策日志与调试服务 ✅ 已实现（新增）

### 9.1 DecisionLogger

- **Ring buffer**: deque(maxlen=100)，滚动记录最近 100 条决策
- **状态摘要**: `_summarize_state()` 轻量级摘要（威胁数/类型、被控数、bot HP 等）
- **统计追踪**: rule/llm/fallback/skipped 计数、API 超时/成功/总耗时
- **统计 API**: `get_stats()` 返回 avg_api_time_ms、各决策类型百分比、action 分布

### 9.2 DebugServer (port 9877)

- **aiohttp** HTTP 服务器
- **Page routes**: `/`, `/bot`, `/map`, `/ai-view`, `/config`, `/history`, `/stats`
- **API routes**: `/api/status`, `/api/bot`, `/api/map`, `/api/ai-view`, `/api/history`, `/api/stats`, `/api/config`
- **POST /api/config/prompt**: 修改 system prompt 并保存到文件

### 9.3 STATE 变化检测

`_state_changed()` 比较关键字段：
- threats: 数量/类型/ghost/距离(>200 变化)
- witches: 数量/angry 状态
- teammates: pinned/incap/bw/hp(>20 变化)
- bot: hp/incap/bw

### 9.4 动态 next_interval

| 场景 | 间隔 | 说明 |
| :--- | :--- | :--- |
| 活跃威胁/被控/倒地 | 1.5s | 需要快速响应 |
| 近期事件 | 2.5s | 中等关注 |
| evade/hold_position | 2.0s | 需要持续关注 |
| 和平状态 | 5.0s | 节省 API |

强制重新评估间隔: `FORCE_REEVAL_INTERVAL = 10.0s`

## 11. 玩家实力多维度评分体系 ✅ 已实现

### 11.1 SourceMod 事件采集

5 维评分全局数组 (每回合重置):

| 维度 | 全局变量 | 事件来源 |
| :--- | :--- | :--- |
| incap | `g_iLLM_PlayerIncap[MAXPLAYERS+1]` | `player_incapacitated_start` |
| pinned | `g_iLLM_PlayerPinned[MAXPLAYERS+1]` | Pin 边缘检测 (`g_bLLM_WasPinned[]` + `LLM_IsPinned()`) |
| revive | `g_iLLM_PlayerRevive[MAXPLAYERS+1]` | `revive_success` / `defibrillator_used` |
| heal | `g_iLLM_PlayerHeal[MAXPLAYERS+1]` | `heal_success` (仅治疗队友) |
| si_kills | `g_iLLM_PlayerSIKills[MAXPLAYERS+1]` | `player_death` (攻击者=survivor, 死者=SI) |

STATE JSON 附加字段:
```json
"player_scores": [
  {"name":"Nick","incap":0,"pinned":0,"revive":0,"heal":0,"si_kills":0},
  {"name":"Ellis","incap":1,"pinned":2,"revive":0,"heal":1,"si_kills":3}
]
```

### 11.2 Python PlayerScorer

加权评分计算:
- heal × 3.0 + revive × 2.5 + si_kills × 1.5 + incap × (-2.0) + pinned × (-1.0)

等级划分: S(≥10) / A(≥5) / B(≥2) / C(≥0) / D(<0)

决策建议注入:
- 团队 D 级 → "优先生存和治疗"
- 高 incap 队友 → "保持近距离掩护"
- Bot 自身 D 级 → "避免前线，专注辅助"
- Bot 高治疗分 → "保持治疗角色"

## 14. 地图经验学习与知识复用 ✅ 已实现

### 14.1 SQLite 存储架构

```sql
CREATE TABLE map_experiences (
    id INTEGER PRIMARY KEY,
    map_name TEXT NOT NULL,
    flow_range TEXT NOT NULL,       -- e.g. "0-1000", "1000-2000"
    situation_hash TEXT NOT NULL,   -- MD5 of key state features
    action TEXT NOT NULL,
    target TEXT DEFAULT '',
    outcome TEXT NOT NULL,          -- pending/survived/incapped/team_wipe/escaped
    survival_time REAL DEFAULT 0,
    si_kills_after INT DEFAULT 0,
    teammate_deaths INT DEFAULT 0,
    timestamp REAL NOT NULL
);
```

索引: `(map_name, flow_range)`, `(situation_hash)`

### 14.2 Situation Hash 特征

```python
features = {
    "threats_count": len(threats),
    "threats_types": sorted([t.type for t in active_threats]),
    "pinned_count": sum(1 for m in teammates if m.pinned),
    "incap_count": sum(1 for m in teammates if m.incap),
    "bot_incap": bot.incap,
    "common_count": state.common_count,
    "has_fire": len(fire_areas) > 0,
    "has_acid": len(acid_areas) > 0,
    "witch_angry": any(w.angry for w in witches),
}
```

### 14.3 Flow 分桶

每 1000 单位一个 bucket: `flow=350 → "0-1000"`, `flow=1500 → "1000-2000"`

### 14.4 回合结果机制

- 每次决策 → `record_decision()` (outcome=pending)
- `mission_lost` 事件 → `ROUND_OUTCOME {"map":"c1m1_hotel","outcome":"team_wipe"}`
- `map_transition` 事件 → `ROUND_OUTCOME {"map":"c1m1_hotel","outcome":"escaped"}`
- Python 接收 → `record_round_outcome()` → 批量更新 pending → 实际结果

### 14.5 经验注入 LLM

```python
past_exp = await map_experience.get_experience(state, limit=3)
# 输出示例:
# [Map Experience]
# - attack_si(smoker): survived x5 (survival_rate=0.8)
# - follow_team(): team_wipe x2 (survival_rate=0.0)
```
